# 公众号写作规范与模板（大众向）

> 适用：AI 知识分享号 · 工具实战 / 技术科普 / 应用案例 / 行业观察 / 学习路径  
> 目标读者：对 AI 好奇、想用起来的普通人（非从业者内部复盘）  
> 与旧版 `文章模板.md` 并存；**写稿与周更优先遵守本文件**。

---

## 一、总原则（先过这关再动笔）

1. **写给「正在刷手机的读者」**，不是写给编辑部或自己。少用「本周新闻」「行业复盘」「普通人该怎么读」这类内部口吻。
2. **每篇必须有一个对读者有用的承诺**：读完能做什么、少踩什么坑、换什么看法。没有用处就不发。
3. **新闻只是素材，不是文章本身。** 行业观察类尤其要把「发生了什么」翻译成「和你有什么关系」。
4. **像朋友聊天，不像通稿。** 用「你」；少用「笔者认为」「综上所述」「值得注意的是」。
5. **标题和小标题都要「有画面、有利益」**，不要「第一点 / 第二点 / 总结一下」。

---

## 二、禁止与慎用（口吻红线）

### 禁止出现的说法（或等价改写）
- 「普通人该怎么读这周新闻」「看完这篇你就懂行业了」——太说教、太像教案
- 「本周热点汇总」「信息太碎我帮你串一下」——可以保留「串起来」的意图，但标题/小节不要自我指涉
- 「一句话总结」「核心看点如下」堆砌——改成具体结论
- 「站队」「叙事」「盘点」「复盘」（对大众正文慎用）

### 小节标题怎么写
| 不好（内部感） | 更好（读者感） |
|---|---|
| 安全线：大厂开始谈踩刹车 | 大厂为什么突然说「先别跑太快」 |
| 普通人该怎么读这周新闻 | 这三件事，会直接碰到你的日常 |
| 资本线继续贵 | 编程助手为什么还在疯狂吸金 |
| 写在最后 | 今天看完，你可以先做这几步 |

原则：**小节标题 = 读者会关心的一句完整意思**，不是栏目编号标签。

---

## 三、篇幅与结构（填空模板）

- 字数：**1500–2500 字**（手机 3–5 分钟）
- 无 YAML frontmatter；正文以 `# 标题` 开头
- 文件名：`编号-标题.md`（草稿目录续号）

```markdown
# 【标题：利益点 + 数字/对比，建议 ≤25 字】

【导语 100–150 字】
- 从一个具体场景、疑惑或反差切入（不要从「本周有很多新闻」切入）
- 点明这篇能帮读者解决什么
- 不剧透全部结论，但要给期待

---

## 【小节标题：读者能听懂的一句完整话】

【观点 1–2 句】→【例子/对比/类比】→【和你有什么关系，1–2 句】

（共 3–5 个小节，行业观察可按「现象→意味着什么→你怎么用」展开，而不是按「安全/政策/资本」内部标签硬切）

---

## 今天看完，你可以先做这几步

【3–4 条可执行行动，越具体越好】

【一句开放问题，方便评论】

如果有帮助，欢迎点赞、在看、转发～

**下期预告**：《……》
```

---

## 四、分栏目补充

### 行业观察（含「周更 / 简报改编」）
- **一篇只打一个主题钉子**（例如：一边谈安全一边狂推产品，对你选工具意味着什么），不要做成七条新闻目录。
- 每引用一条新闻，后面必须跟一句「所以你可以…… / 你会看到……」。
- 避免「线」字标签（安全线、产品线、资本线）做小标题；可在正文里自然带过。
- 结尾行动建议要能本周就做，不要空喊「关注行业趋势」。

### 工具实战 / 学习路径
- 步骤可复制；截图/操作路径写清楚；声明适用版本若已知。

### 技术科普
- 先类比再术语；术语出现即白话解释。

## 五、发布前自检（勾完再交稿）

- [ ] 标题有没有「给读者的好处」？
- [ ] 有没有「教读者如何读新闻 / 复盘本周」的说教小节？有则改掉
- [ ] 小标题能不能单独拿出来当朋友圈句子？
- [ ] 删掉所有新闻后，文章是否还剩「对你有用」的结论？
- [ ] 行动建议是否具体到场景？
- [ ] 有没有堆术语、堆融资数字却不解释含义？
- [ ] CTA + 下期预告是否齐全？

## 六、与仓库流程的关系

1. 选题：参考 `内容选题池.md` + 近期 AI 动态简报（简报是素材，不是成稿）
2. 写作：遵守**本规范**
3. 存放：`公众号内容/草稿/编号-标题.md`
4. 发布：微信后台手工粘贴（见 `发布流程清单.md`）→ 移到 `已发布/`

旧文件 `文章模板.md` 仍可作极简提纲；**冲突时以本文件为准**。
