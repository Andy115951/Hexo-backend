# 公众号写作规范与模板（大众向）

> 适用：AI 知识分享号 · 工具实战 / 技术科普 / 应用案例 / **AI观察周报（行业观察）** / 学习路径  
> 目标读者：对 AI 好奇、想用起来的普通人（非从业者内部复盘）  
> 与旧版 `文章模板.md` 并存；**写稿与周更优先遵守本文件**。

---

## 一、总原则（先过这关再动笔）

1. **写给「正在刷手机的读者」**，不是写给编辑部或自己。少用「本周新闻」「行业复盘」「普通人该怎么读」这类内部口吻。
2. **每篇必须有一个对读者有用的承诺**：读完能分清什么、少踩什么坑、换什么看法。没有用处就不发。
3. **新闻只是素材，不是文章本身。** 行业观察 / AI观察周报类尤其要把「发生了什么」翻译成「和你有什么关系」。
4. **像朋友聊天，不像通稿。** 用「你」；少用「笔者认为」「综上所述」「值得注意的是」。
5. **标题和小标题都要「有画面、有利益」**，不要「第一点 / 第二点 / 总结一下」。

---

## 二、禁止与慎用（口吻红线）

### 禁止出现的说法（或等价改写）
- 「普通人该怎么读这周新闻」「看完这篇你就懂行业了」——太说教、太像教案
- 「本周热点汇总」「信息太碎我帮你串一下」——可以保留「串起来」的意图，但标题/小节不要自我指涉
- 「一句话总结」「核心看点如下」堆砌——改成具体结论
- 「站队」「叙事」「盘点」「复盘」（对大众正文慎用）
- **「今天看完，你可以先做这几步」「本周你要做…」等行动清单 / 作业式收尾**——观察周报不是自助作业；结尾用轻收束，不派任务

### 小节标题怎么写
| 不好（内部感） | 更好（读者感） |
|---|---|
| 安全线：大厂开始谈踩刹车 | 大厂为什么突然说「先别跑太快」 |
| 普通人该怎么读这周新闻 | 这三件事，会直接碰到你的日常 |
| 资本线继续贵 | 编程助手为什么还在疯狂吸金 |
| 今天看完，你可以先做这几步 | 本周信号，一句话收束 |

原则：**小节标题 = 读者会关心的一句完整意思**，不是栏目编号标签。

---

## 三、篇幅与结构（填空模板）

- 字数：**1500–2500 字**（手机 3–5 分钟）
- 无 YAML frontmatter；正文以 `# 标题` 开头
- 文件名：`编号-标题.md`（草稿目录续号）

```markdown
# 【标题：利益点 + 数字/对比，建议 ≤25 字】

【导语 100–150 字】
- 从一个具体场景、疑惑或反差切入（不要从「本周有很多新闻」切入）
- 点明这篇能帮读者分清什么、看到什么
- 不剧透全部结论，但要给期待

---

## 【小节标题：读者能听懂的一句完整话】

【观点 1–2 句】→【例子/对比/类比】→【和你有什么关系，1–2 句】
来源：[标题](url)   ← 关键事实后尽量跟一行出处

（共 3–5 个小节，行业观察可按「现象→意味着什么→和你有什么关系」展开，而不是按「安全/政策/资本」内部标签硬切）

---

## 本周信号，一句话收束

【2–4 句轻收束：本周主线画面，不要行动清单】

【一句开放问题，方便评论——可选】

如果有帮助，欢迎点赞、在看、转发～

**下期预告**：《……》

---

## 延伸阅读（可选，4–6 条）

1. [标题](url)
```

## 四、分栏目补充

### AI观察周报 / 行业观察（含「周更 / 简报改编」）
- **体裁定位：观察与消化，不是作业。** 把简报素材改编成大众向周报：帮读者看懂信号，不布置「本周要做的 3 件事」。
- **一篇只打一个主题钉子**（例如：一边谈安全一边狂推产品，对你意味着什么），不要做成七条新闻目录。
- 每引用一条新闻，后面必须跟一句「所以你会看到…… / 这意味着……」，**不要**跟「所以你本周要去……」。
- 避免「线」字标签（安全线、产品线、资本线）做小标题；可在正文里自然带过。
- **结尾用「周报收束」**：短收束本周信号 + 可选评论提问 + 点赞在看转发 + 下期预告。  
  **禁止**：「今天看完，你可以先做这几步」、编号行动清单、说教式「下一步作业」。

### 工具实战 / 学习路径
- 步骤可复制；截图/操作路径写清楚；声明适用版本若已知。
- 此类栏目可以有可执行步骤；**观察周报不要照搬作业式结尾**。

### 技术科普
- 先类比再术语；术语出现即白话解释。

---

## 五、出处与配图（强制）

1. **关键事实必须有原文链接**，优先官方博客、公司新闻稿、监管机构、路透/权威媒体；找不到就删改表述，**绝不编造 URL**。
2. **推荐**在主要事实段落后加一行：`来源：[标题](url)`；也可在关键名词上做行内链接。
3. **配图 / 截图（可选，行业观察鼓励）**：
   - 仓库存放路径：`公众号内容/素材/编号/`（如 `素材/007/`）
   - 正文可用 `![说明](相对路径或 raw GitHub 路径)` 预览
   - **微信后台仍需手工粘贴图片**；仓库配图只作素材备份，不代替发布粘贴
4. 文末可加简短「延伸阅读」（4–6 条），放在 CTA / 下期预告附近即可。

## 七、与仓库流程的关系

1. 选题：参考 `内容选题池.md` + 近期 AI 动态简报（简报是素材，不是成稿；改编时按 **AI观察周报** 体裁）
2. 写作：遵守**本规范**
3. 存放（**双交付，缺一不可**）：
   - Markdown 成稿：`公众号内容/草稿/编号-标题.md`
   - **微信粘贴版 HTML**：`公众号内容/草稿/微信粘贴版/编号-标题.html`（与 md 同编号、同标题；内联样式，浏览器打开后全选 `#js_content` 正文即可复制到公众号后台）
   - 配图素材：`公众号内容/素材/编号/`
4. **周更交付约定**：每周交稿必须同时交付 `.md` + 微信粘贴版 `.html`；只交 markdown、没有粘贴版，视为未完成交付。
5. 发布：用微信粘贴版 HTML 粘贴到后台（见 `发布流程清单.md`）→ 移到 `已发布/`（md 与对应 html 一并归档）

## 八、微信粘贴版 HTML：内容结构检测安全样式（强制）

公众号后台「内容结构检测」会卡非标 `text-align`、以及行高相对字号过小的多行文本。生成 `草稿/微信粘贴版/*.html` 时**一律按下列配方**，不要照搬浏览器默认或编辑器导出的 CSS。

### 允许的 text-align
只用：`left` | `right` | `center` | `justify`（或省略）。  
**禁止**：`start`、`end`、`-webkit-*`、`initial`、`inherit`。多行正文优先显式 `justify`；标题/列表/来源行用 `left`。

### line-height 必须「视觉上大于字号」
- 多行正文：优先无单位比例 **`1.75` 或 `2`**（≥ 1.5）；或如 `font-size:16px; line-height:28px`。
- **禁止**：`line-height:1`、仅写 `normal` 导致多行塌缩、以及 px 行高 < px 字号。
- 标题、段落、列表、来源小字、表格单元格都要带上行高，不要只靠父级继承碰运气。

### 安全样式配方（粘贴版统一套用）
| 元素 | 内联样式 |
|---|---|
| 外层 `#js_content` | `font-size:16px; line-height:1.75; color:#333; letter-spacing:0.034em; text-align:left;` |
| 标题 `h1/h2` | `font-size:18px; font-weight:bold; line-height:1.75; text-align:left; margin:1.2em 0 0.6em;` |
| 正文 `p` | `font-size:16px; line-height:1.75; text-align:justify; margin:0.8em 0;` |
| 链接 `a` | `color:#576b95; text-decoration:underline;` |
| 来源/小字 | `font-size:14px; line-height:1.75; color:#888; text-align:left;` |
| 列表 `ul/ol/li` | `line-height:1.75; text-align:left;`（字号同正文 16px） |

### 尽量避免
flex / grid、负 margin、`transform`；复杂布局易触发结构检测或粘贴后错乱。

### 自检（粘贴前）
- [ ] 全文 `text-align` 只有 left/right/center/justify
- [ ] 所有多行块 `line-height` 为 ≥1.5 的比例，或 px 行高 > px 字号
- [ ] 无 `start`/`end`/`inherit`/`initial`/`-webkit-*` 对齐值

旧文件 `文章模板.md` 仍可作极简提纲；**冲突时以本文件为准**。
