# Test Case Step 2 Generic — 通用表格用例

**前置条件**：`test-case-step1-generic` 已完成，建模结果已定稿。  
**目标**：将 step1 的结构化分析结果转成可执行、可评审、可排期的测试用例表。  
**边界**：本 skill **不生成自动化代码**，只输出测试用例文档。

---

## 1. 适用场景

当已经有以下任一输入，并且完成了 step1 后，使用本 skill：

1. 基于 PRD / 需求文档产出的 step1 建模结果
2. 基于 commit / PR / diff 产出的 step1 回归分析结果
3. 基于内部机制 / 升级 / 迁移场景产出的 step1 风险建模结果

---

## 2. 基本规则

### 2.1 必须继承 step1 的文档类型

step2 必须继承 step1 中已声明的文档类型：

1. `功能 E2E`
2. `内部机制 / 升级回归`

不要在一份 step2 文档里混写两类目标。

### 2.2 必须继承 step1 的风险裁剪建议

step2 不重新发明优先级，而是根据 step1 中的高风险组合和裁剪建议，组织：

1. `P0`
2. `P1`
3. `P2`

### 2.3 必须从“结构化结果”落到“结构化用例”

输出必须是表格化用例，而不是继续写分析散文。

---

## 3. 输出路径与文件约定

### 3.1 输出路径优先级

1. 如果用户指定输出路径，使用用户指定路径
2. 如果用户未指定，默认输出到当前工作区下：

```bash
tests/test-case-docs/
```

### 3.2 文件命名建议

建议命名：

```text
{topic}-{mode}-step2.md
```

例如：

1. `order-refund-e2e-step2.md`
2. `session-storage-internal-step2.md`

---

## 4. step2 执行流程

### 4.1 先回读 step1

在开始 step2 前，先确认 step1 至少包含：

1. 输入来源
2. 文档类型
3. 范围定义
4. 流程逻辑
5. 数据 / 状态 / 风险分析
6. 测试矩阵
7. 风险裁剪建议

如果 step1 缺少这些信息，不要直接硬写 step2，应先指出不足。

### 4.2 建立优先级

默认规则：

#### P0

必须覆盖：

1. 主流程成功
2. 核心数据正确
3. 关键状态正确
4. 权限 / 隔离 / 安全不能破
5. 关键异常不会导致不可恢复后果
6. 代码变更直接影响到的核心链路

#### P1

建议覆盖：

1. 常见异常
2. 常见边界
3. 回归影响路径
4. fallback / retry / 恢复
5. 关键兼容场景

#### P2

补充覆盖：

1. 极端边界
2. 低频组合
3. 性能退化
4. 低概率兼容风险

### 4.3 按 Given / When / Then 写表格

每条用例至少包含：

1. `ID`
2. `模块`
3. `用例名称`
4. `Given`
5. `When`
6. `Then`
7. `类型`
8. `优先级`

### 4.4 文档类型的不同写法

如果是 `功能 E2E`：

1. `Given` 写用户前置条件、数据条件、环境条件
2. `When` 写用户操作
3. `Then` 写用户可见结果、系统输出和关键状态变化

如果是 `内部机制 / 升级回归`：

1. `Given` 写内部前置条件、数据状态、版本状态、异常注入条件
2. `When` 仍然要写用户动作或系统触发点
3. `Then` 同时写用户结果和内部结果，不允许只写数据库断言

## 8. 覆盖补充

主表格完成后，再补两块。

### 8.1 专项风险补充

只列主表尚未覆盖但风险较高的场景：

```markdown

|--------|-----------|------------|----------|
| {风险描述} | {用例ID / 未覆盖} | {说明} | {建议} |
```

## 9. 禁止行为

1. 禁止跳过 step1 直接写 step2
2. 禁止只写主流程，不写错误和边界
3. 禁止 `Given/When/Then` 过于空泛，无法执行
4. 禁止只有内部断言，没有用户动作和用户结果
5. 禁止把优先级全部堆成 P0
6. 禁止脱离 step1 的风险矩阵重新随意发散

---

## 10. 完成标准

step2 完成时，必须满足：

1. 已继承 step1 的文档类型
2. 已分出 P0 / P1 / P2
3. 每条用例都具备清晰的 Given / When / Then
4. 已覆盖主流程、关键异常、关键边界和回归风险
5. 已补充专项风险和覆盖映射

最终产物应可直接用于：

1. 测试评审
2. 回归排期
3. 手工执行
4. 自动化选点
