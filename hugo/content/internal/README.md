# 内部内容归档说明

这个目录用于保存已经写过、已经分享过，但不适合直接公开发布的内容。

## 内容分层

### 公开文章

位置：`hugo/content/posts/`

适合放：

1. 通用技术文章
2. 已经脱敏的方法论
3. 可以被搜索引擎公开索引的知识文档
4. 不包含内部项目链路、账号、环境、数据、具体故障细节的内容

如果一篇内容要公开，建议单独新建一份公开版文章，而不是直接把内部分享稿改成 `draft: false`。

### 内部私有归档

位置：`hugo/content/internal/private-archive/`

适合放：

1. 已经在内部分享过的讲稿
2. 面向特定角色或团队的材料
3. 包含内部口径、内部流程、未脱敏案例的内容
4. 后续可能抽象成公开文章的原始材料

这些内容默认保持 `draft: true`。

### 成就案例

位置：`hugo/content/work-achievements/`

适合放：

1. 个人工作成果台账
2. 项目复盘
3. 影响、结果、角色、过程沉淀

这类内容默认不公开。  
如果需要公开，建议另写一篇脱敏后的 `posts` 文章，只保留通用方法、背景抽象和可复用经验。

## 公开前检查

公开文章前至少检查：

1. 是否包含公司、产品、项目内部名称
2. 是否包含真实故障链路、内部接口、日志、账号、路径
3. 是否包含未脱敏指标、时间线或业务判断
4. 是否有明显面向特定团队或内部角色的表述
5. 是否可以被不了解上下文的人独立理解

## 推荐流程

1. 内部内容先归档到 `internal/` 或 `work-achievements/`
2. 确认值得公开后，新建一份 `posts/` 公开版
3. 公开版只保留通用方法和可复用经验
4. 公开版确认无敏感信息后，再将 `draft` 改为 `false`
